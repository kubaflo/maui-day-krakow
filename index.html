Try-Fix: How It Works

The workflow can explore alternative fixes and validate candidates on configured emulators or simulators.

1

Analyze Problem & Existing Fix

Reads the issue, PR diff, and gate test results — understands what the fix does and where it falls short

2

Generate Alternative Candidates

Designs a fundamentally different approach — not a tweak, but a new strategy informed by prior failures

3

Build, Deploy & Test on Device

Build, deploy, and run the selected tests when the target environment is available; report failures and gaps

4

Compare & Recommend Best Fix

All candidates are scored against the PR's fix — the winner is recommended with a full diff and rationale

Each candidate goes through expert self-review before testing

The honest boundary

More automation is not the same as proof.

Visible ≠ complete

GitHub does not capture every local AI session, private discussion, failed run, or hour spent by a person.

Passing ≠ correct

Tests cover specific scenarios. Models can miss bugs, misread intent, and suggest incorrect fixes.

Correlation ≠ cause

Release timing, PR size, staffing, and backlog mix also affect activity and merge time.

A real human checkpoint

A label is not a verdict.

“I tested this locally, and it did not resolve the issue.”

Visible signal

This PR carries agent-fix-win / implemented signals in the observed label state.

Author checks

The author reports that the suggestion did not fix the issue and explains a recycled-item concern.

Better standard

Read the discussion, reproduce the behavior, and verify the candidate. Do not treat a label as proof.

Source: dotnet/maui#35358 · author's public follow-up · Example snapshot · 04 Oct 2026. This is a validation limitation, not evidence of a shipped regression caused by AI. Negative labels are too sparse to estimate a failure rate.

Talk track: this is why the human loop matters. Public disagreement is useful evidence, not something to hide behind a success badge.

MAKE FEEDBACK PART OF THE SYSTEMOne example, not a failure-rate estimate

All-PR median merge time rose from 1.689 to 3.004 days. We are not claiming universal speedup, a productivity multiplier, fewer regressions, satisfaction, or zero human interaction.

What would strengthen the story? Validated review findings, comparable cohorts, measured human effort, and post-release outcomes.
